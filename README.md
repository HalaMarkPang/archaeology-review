# 考古-周刊

考古-周刊编选新公布的考古材料、研究论文与理论讨论，介绍主要发现、研究背景及其学术意义。

阅读网站：[考古-周刊](https://halamarkpang.github.io/archaeology-review/)。

网站可按时代筛选和检索本期文献，也可在“往期”中浏览历史刊期、跨期查找文章。每条内容都附原文链接，方便继续阅读。

## 收录范围

周刊主要关注中国旧石器时代至宋元明考古，也收录与中国考古研究问题有关的国际理论和比较研究。辽、金材料归入宋元明；清代及以后的专题研究暂不在范围内。

内容包括发掘简报、发现动态、研究论文、会议纪要、学术演讲和考古学理论。收录时间以资料新近发表或公布为准，发掘工作本身可以早于刊期。

## 选文与解读

选文时，关注材料是否补充了重要缺环、提出了有依据的新解释，或回应了值得继续讨论的问题。同一作品通常只收录一次，有实质进展时再作补充。

每条先介绍研究对象、主要发现和作者的解释，再结合相关领域讨论其意义。篇幅随内容安排：单一发现简写，涉及争论或多种解释时，多交代一些背景和理由。

材料研究侧重“研究意义”，说明新证据如何补充或修正对遗址、技术、社会与历史过程的认识。理论文章侧重“对研究实践的启示”，讲清争论的由来、作者的回应，以及对发掘记录、材料整理、分类分期或历史解释的具体影响。

解读中区分原作者的结论与本刊的补充分析，保留原文中的推测和争议。图片采用论文、报告或发掘单位公布的原图，并注明出处。

## 资料与更新

资料主要来自考古期刊、研究机构和发掘单位的公开发布，公众号等渠道用于补充线索。项目通过自动检索收集资料，使用模型辅助撰写与整理，再对照取得的原文材料复核。

每条的“来源与核验”说明所依据的是摘要、全文、会议记录还是新闻披露，便于读者判断解读的依据与范围。仅有目录和题名的线索，取得足够材料后再编写。

每周五北京时间12:00检索近30天发表的资料，完成选文、撰写与复核后发布。每期数量随合格内容确定。

首期回溯2026年9月1日至10月14日，共收录31条材料与研究。

选文和写作要求见[编选规范](config/research-policy.md)。参与维护可参考[稿件格式与复核要求](docs/editorial-contract.md)及下方操作说明。

### 本地预览

在项目目录运行以下命令，安装依赖、检查内容并生成网页：

```bash
python3 -m pip install -r requirements.txt
python3 -m unittest discover -s tests -v
python3 scripts/build.py
python3 -m http.server 8000 --directory site
```

打开 `http://localhost:8000`。站内检索随网页一起生成，搜索结果会定位到对应刊期的条目。

### 准备资料与稿件

```bash
python3 scripts/discover.py
python3 scripts/editorial.py
python3 scripts/review.py
```

这三步分别负责检索资料、整理撰写所需的原文材料、记录每条候选的处理状态。自动采集结束后，继续准备稿件与复核文件，再执行发布。

自动运行时，原文材料可从 GitHub Actions（仓库的自动任务页面）下载，附件名以 `editorial-packet-` 开头，保留14天。完整摘要和补充原文用于撰写、复核，不随公开记录批量上传。

模型稿与复核文件按[稿件格式与复核要求](docs/editorial-contract.md)准备。项目的采集脚本不调用模型服务；撰写使用什么工具，由维护者选择。

### 导入与发布

稿件完成复核后，先检查，再导入。以下日期为示例，须换成本次资料的采集日期：

```bash
python3 scripts/review.py --date 2026-10-16 --drafts .cache/drafts.json --review-file .cache/review.json --dry-run
python3 scripts/review.py --date 2026-10-16 --drafts .cache/drafts.json --review-file .cache/review.json --publish
python3 scripts/build.py
```

第一条命令只检查，第二条才写入新刊期。标题、正文、评述或证据在复核后发生变化，需要重新核对；同日已有刊期不会被自动覆盖。更正旧刊期时，同步更新更正说明和复核记录；涉及首期正文时，还需更新其内容校验记录。

提交并推送到 `main` 后，仓库会自动检查、生成网页，再通过 GitHub Pages 发布。定时采集提交新记录后，也会触发网页更新。自动任务可能排队延迟，可在 GitHub Actions 查看是否完成。

### 文件位置与检索设置

| 位置 | 用途 |
|---|---|
| `content/issues/` | 正式刊期及正文 |
| `content/candidates/` | 候选题录、检索范围和未完成事项 |
| `content/audits/` | 每条候选是否入选、等待补充或需要复核的记录 |
| `content/status.json` | 最近一次处理的状态，不代表已经发布新刊期 |
| `content/corrections/` | 旧刊期的更正说明 |
| `content/migrations/` | 首期旧稿的校验记录与核验范围 |
| `.cache/` | 撰写用原文、模型稿和复核文件，不提交到公开仓库 |

检索设置统一放在 `config/discovery.json`。期刊优先用正式编号定位，没有编号时按刊名查找并核对。调整来源时，应同时填写可访问的地址和检查方式；仅增加一个名称不会扩大实际检索范围。检索达到设定上限时，仍按未完成处理。

普通刊期目前最多12条，同一时代或理论组最多4条；首期回溯单独保留。数量上限可在上述设置中调整。访问失败或未查完的来源会记录在候选资料中，检索结果不视为完整目录。
