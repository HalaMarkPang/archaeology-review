# 考古-周刊

考古-周刊是按周编选考古材料与研究的静态网站。每期收录新近公布的考古材料、研究论文与理论讨论，说明其主要发现、研究背景与学术意义，并逐条注明所据材料与核验范围。

网站：[本期阅读](https://halamarkpang.github.io/archaeology-review/) · [往期与检索](https://halamarkpang.github.io/archaeology-review/archive/index.html)

## 解决的问题

追踪新近考古材料时，常见困难包括：

1. 材料分散于考古期刊、研究机构、发掘单位与公众号，逐一追踪成本高。
2. 二次报道常不区分原作者结论与转述者推断，推测被写成定论。
3. 报道未说明所据材料是摘要、全文还是新闻披露，读者无法判断解读的依据与范围。
4. 发表时间界定不清，各期收录范围重叠或遗漏。

## 工作机制

### 收录范围

时代上起旧石器时代，下迄宋元明，以中国考古为主，兼收与中国考古研究问题相关的国际理论与比较研究。辽、金材料归入宋元明；清代及以后的专题研究不予收录。

体裁包括发掘简报、发掘动态、调查简报、发掘报告、出土文献、馆藏研究、研究论文、会议纪要与学术演讲；考古学理论单列一组。收录以资料新近发表或公布为准，发掘工作本身可早于刊期。

### 选文标准

入选须满足以下条件之一：材料补充重要缺环；解释有据且有新意；所回应的问题值得继续讨论。同一作品通常只收录一次，有实质进展时再作补充。每期篇数依合格稿件数量而定，默认不设上限。

### 资料与核验

资料主要取自考古期刊、研究机构与发掘单位的公开发布，公众号等渠道仅作补充线索。资料经脚本检索收集，由模型辅助撰写与整理，再与所取得的原文逐条复核。仅有目录与题名者，待取得足够材料后再行编写。

选文与写作要求见 [编选规范](config/research-policy.md)，稿件字段与复核要求见 [撰写与复核说明](docs/editorial-contract.md)。

## 工作流程

```text
每周五 12:00（北京时间）由 Cursor 自动化触发
→ 检索收录窗口内的期刊目录、机构发布与补充线索（discover.py）
→ 导出撰写所需的原文材料（editorial.py）
→ 记录各候选的处理状态（review.py）
→ 逐条撰写，并与原文复核
→ 检查并导入新刊期（review.py --publish）
→ 推送至 main，由 GitHub Actions 构建并发布至 GitHub Pages
```

## 约束与边界

1. **收录窗口**：每期收录上周五 12:00 之后至本周五 12:00（含截止时刻）发表或新公布的资料。任务延迟不延长收录范围；非周五运行时，默认使用最近一个已结束的周度窗口。
2. **发表时刻**：落在起止两个周五且仅标日期的资料，须回原始来源核对发表时刻，确认属于本期后方可收录；数据库入库或更新时间不作为发表时间。
3. **未复核不发布**：自动采集仅收集资料并记录候选状态；未经撰写与复核的材料不发布为新刊期。
4. **原文材料不公开**：撰写所用的完整摘要与补充原文仅用于撰写和复核，不提交至公开仓库。
5. **采集不调用模型**：采集脚本不调用模型服务；撰写所用工具由维护者选定。
6. **定时须双向同步**：`config/discovery.json` 中的 `schedule` 仅用于计算收录窗口，不创建定时任务。调整运行时刻时，须同时修改该设置与 Cursor 自动化的定时。
7. **首期范围**：首期覆盖 2026 年 9 月 1 日至 10 月 14 日，收录 31 条，保留其独立范围，不受条数上限约束。

## 阅读方式

- **本期**：按目录逐篇阅读；可按时代筛选、检索正文，并在页首面板切换刊期。筛选后按结果顺序翻篇。
- **往期**：以卡片收录历史刊期，支持跨期检索；从文章返回时保留检索条件与浏览位置。
- **配图**：点击正文配图可查看原图。

## 输出约定

每条依次包含以下内容：

| 组成部分 | 内容 |
|---|---|
| 标题 | 以一句陈述概括主要发现或判断 |
| 正文 | 研究对象、主要发现与作者的解释；篇幅依内容而定，涉及争论或多种解释者详述背景与理由 |
| 研究意义 | 材料研究适用；说明新证据补充或修正了对遗址、技术、社会与历史过程的哪些认识 |
| 对研究实践的启示 | 理论文章适用；交代争论由来与作者回应，说明其对发掘记录、材料整理、分类分期或历史解释的影响 |
| 配图 | 采用论文、报告或发掘单位公布的原图，并注明出处 |
| 来源与核验 | 注明所据为摘要、全文、会议记录或新闻披露，以及核对范围 |
| 原文链接 | 指向原始出处 |

解读区分原作者结论与本刊分析；原文中的推测按原措辞转述，不提高其确定程度。

### 本地构建

于项目目录执行以下命令，安装依赖、运行测试并生成网页：

```bash
python3 -m pip install -r requirements.txt
python3 -m unittest discover -s tests -v
python3 scripts/build.py
python3 -m http.server 8000 --directory site
```

浏览器访问 `http://localhost:8000`。站内检索随网页一并生成，检索结果定位至对应刊期的条目。

### 采集与撰写准备

```bash
python3 scripts/discover.py
python3 scripts/editorial.py
python3 scripts/review.py
```

三条命令依次检索资料、导出撰写所需的原文材料、记录各候选的处理结果。补跑某一期时，指定原定周五的日期，例如 `python3 scripts/discover.py --date 2026-10-23`；加 `--show-window` 仅查看起止时间。

GitHub Actions 中的采集任务仅供手动补跑。该任务产生的原文材料可在运行页面下载，附件名以 `editorial-packet-` 开头，保留 14 天。

稿件与复核文件按 [撰写与复核说明](docs/editorial-contract.md) 准备。

### 导入与发布

稿件复核完毕后，先检查，后导入。下列日期为示例，须改为本次资料的采集日期：

```bash
python3 scripts/review.py --date 2026-10-16 --drafts .cache/drafts.json --review-file .cache/review.json --dry-run
python3 scripts/review.py --date 2026-10-16 --drafts .cache/drafts.json --review-file .cache/review.json --publish
python3 scripts/build.py
```

第一条命令仅作检查，第二条命令写入新刊期。复核后标题、正文、评述或证据如有改动，须重新核对；同日已有刊期时不自动覆盖。更正旧刊期时，同步更新更正说明与复核记录；涉及首期正文时，另须更新其内容校验记录。

推送至 `main` 后，GitHub Actions 运行检查、生成网页，并发布至 GitHub Pages。手动采集任务提交新记录后，同样触发网页更新。

### 封面与配图

新增刊期封面时，在 `config/covers.json` 填写图片、图注与原始出处。添加封面或正文配图后，先生成网页用小图，再构建检查：

```bash
python3 -m pip install Pillow
python3 scripts/optimize_images.py
python3 scripts/build.py
```

原图、生成的小图与 `config/image-assets.json` 一并提交。网页按屏幕宽度加载小图，点击正文配图仍可查看原图；线上构建无需安装 Pillow。图片来源、许可与维护要求见 [页面图片与图标](docs/assets.md)。

### 检索设置

检索设置统一置于 `config/discovery.json`。期刊优先以正式编号定位，无编号者按刊名检索并核对。调整来源时，须同时填写可访问的地址与检查方式；仅增列名称不扩大实际检索范围。检索达到设定上限、访问失败或未查完的来源，均按覆盖未完成处理，并记入候选资料。

### 条数上限

每期条数默认不设上限。如需限定，于 `config/discovery.json` 修改以下两项：

| 设置项 | 含义 | 默认值 |
|---|---|---|
| `max_issue_items` | 一期收录总数上限 | `null`（不限） |
| `max_per_period` | 同一时代或考古学理论组的收录上限 | `null`（不限） |

取值须为正整数或 `null`，其他取值在运行时报错。设有上限时，超出的合格稿件记为“合格未选”，留存于复核记录；发布前的校验按同一设置执行。

## 目录结构

```text
archaeology-review/
├── config/
│   ├── discovery.json        # 检索来源、运行时刻与条数上限
│   ├── sources.json          # 历史配置位置，运行配置以 discovery.json 为准
│   ├── research-policy.md    # 编选规范
│   ├── covers.json           # 往期卡片的封面、图注与出处
│   └── image-assets.json     # 网页用图及尺寸对应表（自动生成）
├── content/
│   ├── issues/               # 正式刊期及正文
│   ├── candidates/           # 候选题录、检索范围与未完成事项
│   ├── audits/               # 各候选入选、待补充或待复核的记录
│   ├── corrections/          # 旧刊期的更正说明
│   ├── migrations/           # 首期旧稿的校验记录与核验范围
│   └── status.json           # 最近一次处理状态，不表示已发布新刊期
├── docs/
│   ├── editorial-contract.md # 撰写与复核说明
│   ├── assets.md             # 页面图片与图标
│   └── runs/                 # 各期执行、上线与维护记录
├── scripts/                  # 采集、撰写准备、复核导入、构建与图片处理
├── templates/                # 网页模板
├── static/                   # 样式、交互脚本、图标与配图
├── tests/                    # 单元测试
└── .github/workflows/        # 网页发布与手动采集
```

`.cache/`（撰写所用原文、模型稿与复核文件）与 `site/`（构建产物）不提交至仓库。

## 贡献

勘误与资料线索可通过 Issue 提交。已发布刊期的更正记入 `content/corrections/`，并同步更新复核记录。
