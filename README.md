# 考古-周刊

编选新公布的考古材料、研究与理论讨论，说明发现了什么，以及这些发现如何影响我们对过去的认识。

阅读网站：[考古-周刊](https://halamarkpang.github.io/archaeology-review/)。

## 收录范围

以中国旧石器时代至宋元明考古为主，兼收与中国考古研究问题有关的国际理论和比较研究。辽、金材料归入宋元明；专论清代及以后的文章不收录，跨越多个时期的研究按其实际内容判断。

内容包括发掘简报、发现动态、研究论文、会议纪要、学术演讲和考古学理论。文章新发表，不代表发掘工作也发生在同一时期；新闻报道、会议记录和正式论文会分别注明。

## 每条内容怎样写

正文交代研究对象、主要发现和作者的解释。篇幅取决于问题：单一发现简写，涉及争论或多种解释时，补足背景与理由，不统一字数和段数。

材料研究另写“研究意义”，说明它修正了什么认识、解释了什么问题，或增加了哪些值得讨论的证据。不能只重复摘要，或笼统地说“丰富了认识”。

考古学理论另写“对研究实践的启示”。先讲清作者回应的争论，再说明对发掘记录、材料整理、分类分期或历史解释有什么影响。例如，器物相似可以作为分类的依据，但若要进一步解释为人群迁徙，还需要其他证据支持。

作者的结论与本刊补充的分析应分清；可能的解释保留其不确定性。每条附原文链接，“来源与核验”可展开查看实际读到了摘要、全文还是会议记录，以及尚未核实的内容。图片使用有出处的原图并注明来源。

## 怎样检索和核对

检索范围包括所配置的期刊、考古机构发布页面和公众号线索。检索会继续查看后续页面，记录哪些来源已经检查、哪些仍未完成。网页打不开、目录是图片或后续页面无法确认时，会保留说明，不将其算作已经查全。搜狗微信仅用于发现线索，不能代表某个公众号的全部文章。

取得材料后，由模型撰写，再对照来源复核最终稿。只有目录或题名的线索，需要补到足够的原文材料后才能写入正式刊期。复核时既看事实是否准确，也看研究意义和实践启示的推理是否有依据；程序检查不能替代这一步。

同一篇作品会合并重复记录。已经刊载的作品通常不再收录，确有实质更新时须说明。普通刊期最多12条，同一时代或理论组最多4条，不为凑足数量降低标准。

## 更新与首期说明

每周五北京时间12:00自动检索近30天发表的资料，并保存候选记录。自动检索完成后，还需要撰写和复核；没有完成这两步，不会新增正式刊期。网站在完成检查和发布后更新，实际检索情况以每次记录为准。

首期回溯2026年9月1日至10月14日，共31条，不适用普通刊期的数量上限。原稿由其他模型撰写；历史说明曾标注Grok 4.7 High，但未保留每条的运行记录，不能确认逐条生成过程。2026年10月16日对文字、分类、来源说明和评述作了复核与修订，未重新取得原文的部分仍保留核验限制。

详细要求见[编选规范](config/research-policy.md)。维护者需要的文件格式见[稿件格式与复核要求](docs/editorial-contract.md)。

### 本地预览

在项目目录运行以下命令，安装依赖、检查内容并生成网页：

```bash
python3 -m pip install -r requirements.txt
python3 -m unittest discover -s tests -v
python3 scripts/build.py
python3 -m http.server 8000 --directory site
```

打开 `http://localhost:8000`。站内检索随网页一起生成，搜索结果会定位到对应刊期的条目。

### 准备资料与稿件

```bash
python3 scripts/discover.py
python3 scripts/editorial.py
python3 scripts/review.py
```

这三步分别负责检索资料、整理撰写所需的原文材料、记录每条候选的处理状态，不会自动生成中文稿或发布新刊期。

自动运行时，原文材料可从 GitHub Actions（仓库的自动任务页面）下载，附件名以 `editorial-packet-` 开头，保留14天。完整摘要和补充原文用于撰写、复核，不随公开记录批量上传。

模型稿与复核文件按[稿件格式与复核要求](docs/editorial-contract.md)准备。项目的采集脚本不调用模型服务；撰写使用什么工具，由维护者选择。

### 导入与发布

稿件完成复核后，先检查，再导入。以下日期为示例，须换成本次资料的采集日期：

```bash
python3 scripts/review.py --date 2026-10-16 --drafts .cache/drafts.json --review-file .cache/review.json --dry-run
python3 scripts/review.py --date 2026-10-16 --drafts .cache/drafts.json --review-file .cache/review.json --publish
python3 scripts/build.py
```

第一条命令只检查，第二条才写入新刊期。标题、正文、评述或证据在复核后发生变化，需要重新核对；同日已有刊期不会被自动覆盖。修改旧刊期须保留更正说明，并更新对应的复核记录。首期另有校验记录，正文变化后也须同步更新。

提交并推送到 `main` 后，仓库会自动检查、生成网页，再通过 GitHub Pages 发布。定时采集提交新记录后，也会触发网页更新。自动任务可能排队延迟，可在 GitHub Actions 查看是否完成。

### 文件位置与检索设置

| 位置 | 用途 |
|---|---|
| `content/issues/` | 正式刊期及正文 |
| `content/candidates/` | 候选题录、检索范围和未完成事项 |
| `content/audits/` | 每条候选是否入选、等待补充或需要复核的记录 |
| `content/status.json` | 最近一次处理的状态，不代表已经发布新刊期 |
| `content/corrections/` | 旧刊期的更正说明 |
| `content/migrations/` | 首期旧稿的校验记录与核验范围 |
| `.cache/` | 撰写用原文、模型稿和复核文件，不提交到公开仓库 |

检索设置统一放在 `config/discovery.json`。期刊优先用正式编号定位，没有编号时按刊名查找并核对。调整来源时，应同时填写可访问的地址和检查方式；仅增加一个名称不会扩大实际检索范围。检索达到设定上限时，仍按未完成处理。
