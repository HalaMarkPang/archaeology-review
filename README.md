# 考古-周刊

考古-周刊编选新近公布的考古材料、研究论文与理论讨论，介绍其主要发现、研究背景与学术意义。

网站：[考古-周刊](https://halamarkpang.github.io/archaeology-review/)。本期文献可按时代筛选与检索，宽屏页面的侧栏目录标示当前阅读条目，配图可点击放大；「往期」收录历史刊期，支持跨期检索。每条均附原文链接与来源核验说明。

## 收录范围

时代上起旧石器时代，下迄宋元明，以中国考古为主，兼收与中国考古研究问题相关的国际理论与比较研究。辽、金材料归入宋元明；清代及以后的专题研究不在收录范围之内。

体裁包括发掘简报、发现动态、研究论文、会议纪要、学术演讲与考古学理论。收录以资料新近发表或公布为准，发掘工作本身可早于刊期。

## 选文与解读

选文的标准有三：材料补充重要缺环，解释有据且有新意，或所回应的问题值得继续讨论。同一作品通常只收录一次，有实质进展时再作补充。

每条先述研究对象、主要发现与作者的解释，再就所在领域论其意义。篇幅依内容而定：单一发现从简；涉及争论或多种解释者，详述背景与理由。

材料研究设「研究意义」，说明新证据补充或修正了对遗址、技术、社会与历史过程的哪些认识。理论文章设「对研究实践的启示」，交代争论的由来与作者的回应，并说明其对发掘记录、材料整理、分类分期或历史解释的具体影响。

解读区分原作者的结论与本刊的分析，原文中的推测与争议照录。配图采用论文、报告或发掘单位公布的原图，并注明出处。

## 资料与核验

资料主要取自考古期刊、研究机构与发掘单位的公开发布，公众号等渠道用作补充线索。资料经自动检索收集，由模型辅助撰写与整理，再与所取得的原文逐条复核。

每条的「来源与核验」注明所据为摘要、全文、会议记录或新闻披露，以示解读的依据与范围。仅有目录与题名者，待取得足够材料后再行编写。

## 更新周期

每周五 12:00（北京时间）运行，收录上周五 12:00 之后至本周五 12:00（含截止时刻）发表或新公布的资料，经选文、撰写与复核后发布。每期篇数依合格内容而定。

首期已完成验证，覆盖 2026 年 9 月 1 日至 10 月 14 日，收录材料与研究 31 条，单独保留原有范围。

选文与写作要求见[编选规范](config/research-policy.md)，稿件格式与复核要求见[模型稿与证据合同](docs/editorial-contract.md)。

### 定时运行

每周的采集、撰写、复核与发布由 Cursor 自动化在云端执行，运行时刻即 `config/discovery.json` 中 `schedule` 所设时刻（现为每周五 12:00，北京时间）。调整运行时刻，须同时修改该设置与 Cursor 自动化的定时，二者不会自动同步。GitHub Actions 中的采集任务不另设定时，仅供手动补跑。

### 本地预览

于项目目录执行以下命令，安装依赖、运行测试并生成网页：

```bash
python3 -m pip install -r requirements.txt
python3 -m unittest discover -s tests -v
python3 scripts/build.py
python3 -m http.server 8000 --directory site
```

浏览器访问 `http://localhost:8000`。站内检索随网页一并生成，检索结果定位至对应刊期的条目。

### 采集与撰写准备

```bash
python3 scripts/discover.py
python3 scripts/editorial.py
python3 scripts/review.py
```

三条命令依次检索资料、导出撰写所需的原文材料、记录各候选的处理结果。自动采集完成后，须另行准备稿件与复核文件，方可发布。

检索窗口以原定周五 12:00 为截止时刻。任务延迟不延长收录范围；非周五运行时，默认使用最近一个已经结束的周度窗口。补跑某一期可指定原定周五的日期，例如 `python3 scripts/discover.py --date 2026-10-23`；加 `--show-window` 可只查看起止时间。

仅标日期的来源按日期检索。若资料落在起止两个周五，却没有发表时刻，须回原始来源核对，确认属于本期后再收录；不能将数据库入库或更新时间当作发表时间。

在 GitHub Actions 中手动运行采集所产生的原文材料，可在该次运行页面下载，附件名以 `editorial-packet-` 开头，保留 14 天。完整摘要与补充原文仅用于撰写和复核，不提交至公开仓库。

稿件与复核文件按[模型稿与证据合同](docs/editorial-contract.md)准备。采集脚本不调用模型服务；撰写所用工具由维护者选定。

### 导入与发布

稿件复核完毕后，先检查，后导入。下列日期为示例，须改为本次资料的采集日期：

```bash
python3 scripts/review.py --date 2026-10-16 --drafts .cache/drafts.json --review-file .cache/review.json --dry-run
python3 scripts/review.py --date 2026-10-16 --drafts .cache/drafts.json --review-file .cache/review.json --publish
python3 scripts/build.py
```

第一条命令仅作检查，第二条方写入新刊期。复核后标题、正文、评述或证据如有改动，须重新核对；同日已有刊期者，不自动覆盖。更正旧刊期时，同步更新更正说明与复核记录；涉及首期正文者，另须更新其内容校验记录。

推送至 `main` 后，仓库自动运行检查、生成网页，并经 GitHub Pages 发布。在 GitHub Actions 中手动运行采集并提交新记录后，亦触发网页更新。自动任务可能排队延迟，完成情况可在 GitHub Actions 查看。

### 文件位置

| 位置 | 用途 |
|---|---|
| `content/issues/` | 正式刊期及正文 |
| `content/candidates/` | 候选题录、检索范围与未完成事项 |
| `content/audits/` | 各候选入选、待补充或待复核的记录 |
| `content/status.json` | 最近一次处理的状态，不表示已发布新刊期 |
| `content/corrections/` | 旧刊期的更正说明 |
| `content/migrations/` | 首期旧稿的校验记录与核验范围 |
| `.cache/` | 撰写所用原文、模型稿与复核文件，不提交至公开仓库 |
| `templates/` | 网页模板 |
| `static/` | 网页样式、交互脚本、图标与配图 |

### 检索设置

检索设置统一置于 `config/discovery.json`。期刊优先以正式编号定位，无编号者按刊名检索并核对。调整来源时，须同时填写可访问的地址与检查方式；仅增列名称，不扩大实际检索范围。检索达到设定上限者，仍按未完成处理。

访问失败或未查完的来源记入候选资料，检索结果不视为完整目录。

### 条数上限

每期条数默认不设上限，合格稿件全部收录。如需限定，于 `config/discovery.json` 修改以下两项：

| 设置项 | 含义 | 默认 |
|---|---|---|
| `max_issue_items` | 一期收录总数上限 | `null`（不限） |
| `max_per_period` | 同一时代或考古学理论组的收录上限 | `null`（不限） |

取值须为正整数或 `null`，其他取值在运行时报错。例如设为 `12` 与 `4`，即一期至多 12 条、同组至多 4 条。设有上限时，超出的合格稿件记为「合格未选」，留存于复核记录；发布前的校验按同一设置执行。首期回溯不受此限。
